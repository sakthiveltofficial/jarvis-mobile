# Jarvis for Android

The phone companion for [Jarvis](https://github.com/sakthiveltofficial/jarvis), the desktop voice assistant.

- **Talk or chat** to desktop Jarvis from your phone, with the same light, gradient-tile look (and dark mode).
- **Let Jarvis use your phone**: read the screen, tap, swipe, type, open apps, read and reply to notifications,
  send SMS, make calls, search contacts, move files between phone and PC, find your phone, and more.
- **Private by design**: the phone talks straight to your PC over your Wi-Fi or Tailscale. No cloud relay.
  Every message is end-to-end encrypted (AES-256-GCM) with a key created when you pair.

## Install

1. Download the latest `Jarvis-x.y.z.apk` from [Releases](../../releases) on your phone and open it.
   Allow "Install unknown apps" when Android asks.
2. On your PC, open Jarvis → ⚙ → **Connections** → **My phone** → **Pair a phone**.
3. Open Jarvis on the phone and scan the QR code. Both devices must be on the same network (or both on Tailscale).
4. In the app's **Phone** tab, turn on what you want Jarvis to be able to do.

> Android 13+ blocks Accessibility and Notification access for sideloaded apps. If the switch is greyed out, open
> **App info → ⋮ → Allow restricted settings**, then try again.

## What the phone can do for Jarvis

| Capability | How | Turn on |
|---|---|---|
| Read the screen, tap, swipe, type, back/home/recents | Accessibility service | Phone tab → Screen control |
| Screenshots | Accessibility (Android 11+), or MediaProjection on Android 10 | comes with Screen control |
| Notifications: list, open, reply, dismiss | Notification listener | Phone tab → Notifications |
| SMS, calls, call log, contacts | Runtime permissions | Phone tab |
| Files: browse, read, write, send to/from PC | All files access | Phone tab → Files |
| Location, ring (find my phone), torch, volume, media keys | System APIs | Phone tab → Location |
| Shell commands, any key event | [Shizuku](https://shizuku.rikka.app) (optional "power mode") | Phone tab → Power mode |

Desktop Jarvis gets a `phone` tool for all of this. Risky actions (sending messages, calling, deleting or
overwriting files, shell commands) go through Jarvis's usual "ask before acting" confirmations, which you can
answer on the PC or on the phone.

## How it works

```
┌─────────── Phone (this app) ───────────┐         ┌──────── PC (desktop Jarvis) ────────┐
│ React Native UI (Expo)                 │         │ phones.py  "phone hub" on :8767     │
│   Talk · Phone · Settings              │         │   pairing QR, device keys           │
│ modules/jarvis-bridge (Kotlin)         │  ws://  │   forwards chat events to phones    │
│   BridgeService  (foreground service)  │◄───────►│   phone tool → call → result        │
│   AccessibilityService, Notifications  │ AES-GCM │ agent.py  the same Jarvis brain,    │
│   PhoneTools, Shizuku, MediaProjection │         │   memory, voice and confirmations   │
└────────────────────────────────────────┘         └─────────────────────────────────────┘
```

- **Pairing**: the QR code holds the PC's addresses (LAN and Tailscale), a one-time pairing id and a 32-byte
  secret. The phone proves it has the secret, and the PC answers with a long-term device key (encrypted under that
  secret). The secret expires after 10 minutes and works once. The device key is stored wrapped by the Android
  Keystore.
- **Connection**: a WebSocket kept alive by a foreground service, with every frame sealed with AES-256-GCM and bound
  to a per-connection random challenge and direction, plus sequence numbers against replay. It tries each known
  address, reconnects with backoff, reconnects when the network changes and after a reboot.
- **Voice**: push-to-talk records 16 kHz audio on the phone; the PC transcribes it with your configured speech-to-text
  (local Whisper by default) and, if you like, speaks the reply back through the phone.

### What we reused

- [Shizuku API](https://github.com/RikkaApps/Shizuku-API) (Apache-2.0) for the optional power mode.
- Expo modules: camera (QR scanning), fonts, linear gradients, haptics; `react-native-svg`; OkHttp for the WebSocket.
- We looked at [DroidRun Portal](https://github.com/droidrun/droidrun-portal) (AGPL-3.0, so its code isn't copied)
  and [mobile-mcp](https://github.com/mobile-next/mobile-mcp) (Apache-2.0). mobile-mcp works with desktop Jarvis
  today without this app: add it under ⚙ → Connections → Apps and connect the phone over (wireless) ADB.

## Develop

```bash
npm ci
npx expo run:android          # builds a dev client onto a connected phone/emulator (needs the Android SDK)
npm run typecheck
```

Native code lives in `modules/jarvis-bridge/android`. The `android/` folder is generated by `expo prebuild` and
isn't committed.

## Releases (CI/CD)

`.github/workflows/android.yml` type-checks, generates the native project and builds a release APK on every push and
pull request (the APK is attached to the run). Pushing a tag like `v0.1.1`, or running the workflow by hand with a
tag, publishes a GitHub Release with the APK.

For stable updates (Android only installs an update signed with the same key), add these repository secrets:
`ANDROID_KEYSTORE_BASE64` (base64 of a `.jks`), `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`.
Without them the APK is signed with the shared debug key.

```bash
keytool -genkeypair -v -keystore jarvis.jks -alias jarvis -keyalg RSA -keysize 2048 -validity 10000
base64 -w0 jarvis.jks   # paste into ANDROID_KEYSTORE_BASE64
```
